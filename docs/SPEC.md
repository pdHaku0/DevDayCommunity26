# Dot Link 技術仕様

対象は `prototype/dot-link` ブランチの各自Sites構成です。価値と利用例は[README](../README.md)、導入の実行手順は[SETUP.md](SETUP.md)を参照してください。

この文書は実装の説明です。未確認の実環境動作は末尾の[検証状況](#検証状況2026-10-18)に分けています。

## 構成と責務

```text
利用者A ←→ Dot A                           Dot B ←→ 利用者B
              │                              │
       共通クライアント                 共通クライアント
       秘密鍵・暗号化・復号             秘密鍵・暗号化・復号
              │ 所有者用Plugin                │ 所有者用Plugin
              ▼                              ▼
         本人のSite A ── 署名付き暗号文 ── 本人のSite B
              └─ MCP Events → Dot A           └─ MCP Events → Dot B
```

- **Dot**：本人との会話、送信する内容の判断、受信後の対応。用途別のエージェントや会話シナリオは本リポジトリで実装しません。
- **端点クライアント**：Dotの永続的なクラウドPCで鍵と状態を保持し、署名・暗号化・復号を行います。
- **各自のSite**：ChatGPT認証された所有者操作、登録・接続許可の管理、暗号文の配送・一時保管、イベント通知を担当します。
- **固定の更新配信元**：公開版情報と通知先Siteのorigin・配信状態を管理します。ユーザー間メッセージの中継先ではありません。

実行基盤はChatGPT SitesのCloudflare WorkersとD1、WebはVinext/React、クライアントはNode.js 22.13以上とlibsodiumです。現行の配送先はHTTPS `*.chatgpt.site` に限定しています。Cloudflare Workers等への汎用移植は未実装です。

実装入口：[Worker](../prototype/build/sites-worker.ts)、[サービス](../prototype/server/service.mjs)、[DBスキーマ](../prototype/db/schema.ts)。

## 接続と配送

1. 各端点が暗号鍵と署名鍵を生成し、鍵の所持証明と公開情報を自分のSiteへ登録します。
2. 招待者が署名付きURLを生成し、その招待IDをSiteへ登録します。登録成功後にURLを本人へ返します。
3. 受信側の本人がリンクを自分のDotへ渡します。クライアントが署名・有効期限・Site originを検証し、招待の秘密を暗号化した受領情報を返します。
4. 招待者の端点が受領情報を復号し、保存した秘密との一致を確認して接続を確定します。表示名だけで本人確認したことにはしません。
5. 接続後は、送信側端点が署名・暗号化したパケットを自分のSite経由で相手のSiteへ送ります。受信側Dotはイベントを受けて同期し、端点で検証・復号します。
6. 受信暗号文を端点へ永続保存した後に `ack` を送り、中継側の暗号文を消去します。`ack` は人の既読通知ではありません。

リンクは既存の信頼できる経路で交換します。招待ページは署名検証・QR・コピーを提供し、相手のSiteへのログインやブラウザ上の承認を接続操作にはしません。受信側も自分のSiteと端点の導入が必要です。

署名パケットの `kind` は `accept` / `confirm` / `message` / `disconnect`。送信前に正確なパケットを端点へ保存し、配送結果が不明なら同じパケットを再送します。切断済みの古い接続を再送で復活させず、再接続は新しい招待で行います。

実装：[プロトコル](../prototype/skills/dot-link/scripts/protocol.mjs)、[配送](../prototype/server/federation.mjs)、[招待ページ](../prototype/app/connect/page.tsx)。

## APIと認証

MCPプロトコルは `2026-07-28` を実装しています。利用者は所有者用Pluginを使います。ブラウザで `/mcp` を開く操作はログイン・導入手順ではありません。

| MCPツール | 内容 |
| --- | --- |
| `link_account` | 自分の端点・購読・更新登録エラー等の確認 |
| `link_register` | 公開情報と所持証明による端点登録。既存登録を別の鍵で上書きしない |
| `link_exchange` | クライアントの `operation` と `input` を変更せず実行 |
| `link_unregister` | 明示された本人の依頼で、端点登録と関連するSite内データを削除 |

`link_exchange` の操作は `invite.create` / `dispatch` / `sync` / `ack`。送信本文はクライアントで暗号化してから渡します。ツール定義と入力スキーマの正本は [mcp.mjs](../prototype/server/mcp.mjs)、操作の定義は [service.mjs](../prototype/server/service.mjs)です。

- `/mcp` の所有者操作はSitesが付与する認証済みユーザーIDと端点所有権を照合します。利用者が認証ヘッダーを偽装できる別のWorker originを公開してはいけません。
- `POST /api/federation` はSite間配送用。ChatGPTログイン情報を他のSiteへ送りません。署名・宛先・接続・期限を検証します。
- 配送は検証済みHTTPS originに限定し、リダイレクト禁止、時間・サイズ上限を設定します。
- エラーには `code`、処理段階、再試行可否、`request_id` 等を返します。リモートの応答本文や認証情報をそのままエラーに混ぜません。

## 暗号化と権限の境界

libsodiumのsealed box（X25519 / XSalsa20-Poly1305）とEd25519署名を使います。暗号実装は [crypto.mjs](../prototype/skills/dot-link/scripts/crypto.mjs) にあります。

- E2EEの端点は各Dotの実行環境です。Siteへ本文の平文や秘密鍵を送らない構成であり、本人のDotやその実行・モデル提供基盤からも本文を隠すという意味ではありません。
- Siteには相手の公開情報・通信関係・時刻などが見えます。匿名通信やメタデータ秘匿は提供しません。
- 長期の受信秘密鍵が漏えいした場合のforward secrecyはありません。
- 接続は送受信の許可です。相手からのメッセージは外部の入力であり、主人の指示や他アプリへのアクセス許可にはなりません。記憶・予定・ファイルの開示判断はDot側の本人権限に従います。
- 更新元は固定GitHubと固定配信元を信頼します。独立したリリース署名検証や再現可能ビルドによる供給網検証は実装していません。

## 保存と削除

| 場所 | 保存するもの | 削除・期限 |
| --- | --- | --- |
| Dot端点 | 秘密鍵、公開ID、接続、招待の秘密、受信・送信待ち暗号文 | 永続保存。会話やイベントをまたいで同じ保存先を使う。登録削除でもローカルファイルは残る |
| 各自Site | 所有者ID、公開鍵・表示名・Site origin、接続許可 | 明示的な端点登録削除で関連データとともに削除 |
| 各自Site | 招待情報・暗号化された受領情報 | 招待は7日で失効 |
| 各自Site | メッセージ暗号文・配送パケット／重複防止記録 | 最大24時間。暗号文は受信側の保存後のackでも削除。再送による復活を防ぐID／ハッシュは期限まで保持 |
| 各自Site | イベント購読・コールバック情報・配信待ち | 購読は最大24時間。失効後は再購読と同期で回収 |
| 更新配信元 | 通知先の公開Site origin、配信・適用確認状態 | 登録がなくなったSiteは次の配信時の状態確認で除去 |

期限切れのレコードは利用できません。物理的な掃除は後続操作時に行います。ホスティング基盤のバックアップまで即時削除する保証はありません。

`disconnect` は相手一人との接続解除、`link_unregister` は自分の端点登録と関連データの削除です。後者も端点の鍵・履歴、相手側のコピー、SiteやPluginそのものは削除しません。削除した端点をイベント処理で勝手に再登録しません。

## イベントと自動更新

`link.inbox_changed` は暗号文、接続要求、更新の到着を知らせます。通知本文は `peer_id` のみで、会話本文を含めません。所有者に紐づく購読、コールバック確認、署名付き通知を実装しています。

```text
開発者が固定リポジトリと配信元Siteを更新
  → 各Siteへ更新通知
  → 各Siteが固定配信元の公開版情報を検証
  → MCP EventsでDotを起動
  → dot-linkが同期・保存
  → 検証済みapply_updateをdot-link-setupへ渡す
  → 既存Siteと両Skill・共通クライアントを更新
```

自動更新登録は通常の登録・同期時に行います。有効化ツールや無効化オプション、1時間ごとの確認タスクはありません。鍵・接続・Site IDを維持し、中断時は保存した進捗から再開します。具体的な公開・更新手順は [AUTO_UPDATE.md](../prototype/AUTO_UPDATE.md) を参照してください。

開発者は `release.json` の版を上げ、GitHubへのpushと配信元の公開を完了してから、配信元の `POST /api/updates/publish` に空オブジェクトを送ります。第三者が任意のURLや文章を更新指示として渡すAPIではありません。

通知の受付、Dotの起動、Siteの更新、端点Skillの更新は別の状態です。配信元が確認する `installed_version` はSiteの版であり、Dotの端点更新完了の証明にはなりません。

リクエストに付随する短い再試行と永続キューがありますが、定期実行はしません。継続的な配送失敗には後続操作・同期・再購読等が必要で、一定時間後の再起動は保証しません。プラットフォームが求める本人認証・承認は省略できません。

実装：[イベント](../prototype/server/events.mjs)、[更新](../prototype/server/updates.mjs)、[リリース情報](../prototype/release.json)。

## 開発と再現

リポジトリのルートから実行します。

```sh
npm ci --prefix prototype
npm test --prefix prototype
cd prototype
npx tsc --noEmit
npm run build
```

- [core.test.mjs](../prototype/tests/core.test.mjs)：実暗号による改ざん拒否、独立したSQLiteバックエンド間の接続・配送、所有者分離、再送、切断、保存後ack、イベント署名、登録削除。
- [updates.test.mjs](../prototype/tests/updates.test.mjs)：自動登録・失敗再試行、固定更新元の検証、配信状態、遅延購読での回収。

検証コードは外部の実Dotを起動しません。実利用では、二者が[導入手順](SETUP.md)を完了し、リンク交換後に異なる本文を往復させ、相手側の復号・返信を確認します。手動同期した場合はイベント起動成功と区別してください。

後方互換、旧状態・旧接続の移行、鍵紛失時の復旧、グループ、添付ファイル保管、常時直接P2P、汎用ホスティング対応は対象外です。導入時間にはDotの判断・依存準備・公開・本人操作の待ちが含まれ、所要秒数の保証はありません。
