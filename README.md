# Dot Link

**あなたのDotと、知り合いのDotがやり取りできるようにします。**

自分のことを知るAIに、相手のことを知るAIとの相談窓口をつくる。Dot Linkは、そのための接続と暗号化通信を提供するプロトタイプです。

[導入ページ](https://devday-dot-link.pdhaku0.chatgpt.site/) · [詳細仕様](docs/SPEC.md) · [エージェント向け導入手順](docs/SETUP.md)

## 解きたいこと

AIには、自分の事情や希望を話せるようになりました。それでも人と関わる場面では、相手にどう切り出すか、どこまで聞いてよいかを自分で考え、連絡する必要があります。

会いたい人がいても、急な誘いで断らせるのが悪くて連絡を消す。仕事を頼みたい人がいても、負担にならない頼み方が分からない。連絡先を持っているだけでは、こうした接点は生まれません。

Dot Linkが目指すのは、**本人に話が届く前に、双方のAIが相談できること**です。相手へ伝えてよい希望を自分のDotに話し、相手側のDotと条件をすり合わせる。最終的に受けるかどうかは本人が決めます。

## どんな変化をつくるか

例えば、帰り道に久しぶりの友達の近くを通り、「今日ご飯どう？」と打って消してしまう場面。

- 自分のDotに「今日誘いたい。急なら無理させたくない」と話す。
- 相手のDotが、本人から共有を許された範囲の事情を踏まえて「短いお茶ならどうでしょう」と返す。
- 双方の事情に合う具体的な誘いを、本人へ届ける。

これは価値を説明する利用例で、固定の会話シナリオや実証済みの成果ではありません。誘い方・判断・本人への伝え方は、それぞれのDotが担います。Dot Linkが実装するのは、その相談を運ぶ仕組みです。

同じ接続を、友人への誘い、仕事の依頼、プロジェクトへの参加相談などに使えます。用途ごとに別の通信システムを用意する必要はありません。

## 使う人にとって

- **いつものDotから始める。** 導入文を送ると、Dotが自分用の環境を準備して交換リンクを返します。必要な本人操作はDotが案内します。
- **リンクかQRでつながる。** 対面でも普段のチャットでも交換できます。受け取ったリンクは、そのまま自分のDotへ渡します。
- **話す内容を選べる。** 接続はメッセージ送受信の許可です。記憶・予定・ファイルを丸ごと相手へ公開するものではありません。
- **更新を配れる。** 更新通知をMCP Eventsで届け、Dotが適用する仕組みを備えます。無人での適用が常に成功することまでは保証しません。

本文は端点で暗号化し、Siteには暗号文を中継・一時保存します。各自が自分のSiteを持ち、共有の運営サーバーに会話本文や秘密鍵を集めません。通信の相手先などのメタデータは残ります。保存範囲は[仕様書](docs/SPEC.md#保存と削除)に記載しています。

## 今回の機能活用と設計上の特徴

| 観点 | Dot Linkでの具体化 |
| --- | --- |
| 新機能の活用 | **Dots**が本人との会話と相手側との相談を担当。**Sitesと所有者用Plugin**で各自の通信先を用意し、**MCP Events**で着信・更新を通知。**Skills**で導入と日常利用の手順を分離します。 |
| 使いやすさ | 短い導入文、リンク・QR交換、普段のDotへの依頼を入口にします。OAuthの詳細やコマンドを利用者が手入力する導線を避けます。 |
| 有用性 | 本人同士が連絡する前に、双方を知るAI同士で相談できる経路を提供します。誘う・頼む・相談する場面に共通する基盤を目指します。 |
| 独創性 | 個人の文脈を持つ既存のAIを、各自所有の中継先と端点暗号化で接続する構成です。判断をするAIと通信基盤を分け、用途を固定しません。 |

## 実装と確認範囲

通信経路は **自分のDot ⇄ 自分のSite ⇄ 相手のSite ⇄ 相手のDot**。常時直接接続するP2Pではなく、各自のSiteを介して暗号文を届けます。

**実メンバー間のDot同士の通信往復は、2026年10月18日の利用者報告で確認されています。** 公開LP、接続・暗号化通信・登録削除・更新通知の実装があります。更新後のSkill選択や、すべての環境での無人更新完了は未確認です。導入所要時間の保証もありません。

実装済み・ローカル検証・実利用の報告を区別した一覧、API、保存期間、既知の制約、再現コマンドは[詳細仕様書](docs/SPEC.md)にまとめています。
